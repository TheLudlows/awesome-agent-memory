# LoCoMo：评估大语言模型智能体的超长期对话记忆

**英文题名：** Evaluating Very Long-Term Conversational Memory of LLM Agents

**版本与时间：** 2024 ACL  
**主题：** 长期对话评测  
**原文入口：** [主文](https://aclanthology.org/2024.acl-long.747/) · [arXiv](https://arxiv.org/abs/2402.17753)  
**核对日期：** 2026-10-23  
**阅读依据：** [正文或技术版本](https://aclanthology.org/2024.acl-long.747.pdf)；涉及补充稿的内容单独说明。本文为首版通俗解析，不包含独立实验复现。文中的教学例子与“本文推论”不是论文原始实验。

## 一句话理解

给助手读一段跨很多次见面的聊天，再检查它是否把人物、事件和时间串对，而不是只记住几个关键词。[1]

## 数据怎样产生

论文利用人物设定和带时间联系的事件图，引导 LLM Agent 生成长期对话，再通过人工处理修正不一致与无关内容。它是机器与人协作构造的数据，不应称为未经加工的真实用户聊天记录。[1，§3]

## 不只是一套问答题

论文包含问答、事件总结和多模态对话生成等评测。问答又从单跳、多跳、时间、外部知识与对抗问题等角度检查理解。后续工作常使用其中的 QA 子集，不代表每篇都跑了完整评测。[1，§4]

## 教学例子：人和时间都不能搞混

甲说下周参加比赛，乙说去年参加过类似活动。后来问“谁准备参赛、谁已经参加过”，系统需要区分说话人和时间。如果只检索到“参加比赛”，仍可能答反。

另一个挑战是没出现的事实：不能因为对话很长，就假定某个问题一定有答案。

## 实验证据的含义

论文比较了不同模型与检索方式，显示长期对话理解中仍存在时间、因果与一致性困难。[1，§5] 这些结果依赖当时配置；现在复现应明确数据版本和评测任务，而不是把论文的历史结论当成当前所有模型的固定表现。

## 对基础设施的启示（本文推论）

每条记忆至少要能回到原始说话人、会话、时间与消息位置。提取事实时不要丢掉代词指向和事件发生条件。回答评估也要检查来源归属，避免“记得这件事，但记错是谁”的错误。

## 复现时尤其注意

原论文、后续公开子集以及其他系统改写过的 QA 协议可能不同。记录所用文件、问题类别、是否提供图片说明、是否使用 LLM 裁判。F1 与裁判准确率是不同指标，不能直接比较。

## 与 LongMemEval 的关系

两者都适合对话记忆；LongMemEval 更明确地组织知识更新与拒答等能力，LoCoMo 还提供事件总结和多模态任务。

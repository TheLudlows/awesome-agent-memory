# ReasoningBank：通过推理记忆扩展智能体的自我进化能力

**英文题名：** ReasoningBank: Scaling Agent Self-Evolving with Reasoning Memory

**版本与时间：** 2025 预印本；解析基于 v1 方法  
**主题：** 经验提炼  
**原文入口：** [主文](https://arxiv.org/abs/2509.25140) · [arXiv](https://arxiv.org/abs/2509.25140)  
**核对日期：** 2026-10-23  
**阅读依据：** [正文或技术版本](https://arxiv.org/html/2509.25140v1)；涉及补充稿的内容单独说明。本文为首版通俗解析，不包含独立实验复现。文中的教学例子与“本文推论”不是论文原始实验。

## 一句话理解

把“这次鼠标点了哪里”的流水账，整理成“遇到这类问题应该怎样判断”的经验手册。[1]

## 它解决什么

原始轨迹完整却冗长，直接检索出来可能只带来噪声；只存成功流程，又容易漏掉失败的教训。ReasoningBank 同时从自评成功和失败的经历中提炼可复用的推理策略。

## 核心闭环

新任务先检索相关记忆，用于指导行动；任务结束后判断结果，构造新的经验条目，再纳入记忆库。条目有**标题、简要描述和内容**，重点保存可迁移的策略、理由或操作认识。[1，§3]

论文还提出 MaTTS，通过增加和组织测试时的尝试经验，形成更丰富的对比信号，进一步帮助经验提炼。这部分与更多推理预算相关，比较结果时不能忽略计算成本。

## 教学例子：从具体错误到通用策略

流水账：“先查了 CPU，再查慢 SQL，最后才发现连接数满了。”

更可迁移的经验：“请求超时但 CPU 不高时，不要只沿算力瓶颈排查，应同时检查连接池与排队指标。”

后者更容易用于新任务，但仍应带适用条件。不能把“一次恰好有效”写成所有数据库的普遍规律。

## 实验与边界

论文在网页任务与软件工程任务中研究这种经验闭环，并与存原始轨迹或成功流程等方式比较。[1，§4] 自评结果可能错误，系统会把错误归因固化为长期策略；流式任务顺序也可能影响实验结果。

## 与 Reflexion、Voyager 的关系

Reflexion 让下一轮尝试带着教训；ReasoningBank 更强调跨任务积累通用策略；Voyager 则把行为保存为可执行技能。它们分别突出复盘、策略和代码复用。

## 对基础设施的启示（本文推论）

经验条目可独立于原始执行轨迹，记录来源任务、适用范围、成功与反例。支持合并重复策略与撤回错误策略，比仅提供向量 upsert 更接近长期经验管理的需求。

## 三个不同的问题，不能只用一个相似度分数回答

用户请求“帮我把这段话改得自然一些”，通常不需要外部检索。用户问一个历史事实，可能需要检索；但检索出来的文章即使相关，也未必支持模型写出的全部结论。

Self-RAG 把这些判断拆开：现在需不需要检索？资料相关吗？回答受到资料支持吗？回答对用户有用吗？它让模型学习输出专门的反思 token，将判断与生成结合起来。[1，§3]

这些 token 有训练过的语义。给普通聊天模型加一句“请反思”，并不能算复现 Self-RAG。

<a id="s2"></a>

## 四类标记分别控制什么

| 标记 | 依据什么判断 | 回答什么问题 |
| :--- | :--- | :--- |
| Retrieve | 输入与此前输出 | 需要新检索、不检索，还是继续使用已有资料？ |
| ISREL | 问题和段落 | 这段材料是否与回答有关？ |
| ISSUP | 问题、段落和回答片段 | 回答被充分支持、部分支持，还是不受支持？ |
| ISUSE | 问题和回答 | 回答是否有用？ |

这张表对应论文的分类。[1，表 1] “相关”和“支持”尤其不能混在一起。一份写数据库恢复的文档可能相关，却未必支持“恢复过程绝不丢数据”这种更强的结论。

同样，“有用”与“受支持”不同。回答可以完全忠实地复述一段无关细节，却没有解决用户的问题；也可以看起来很有帮助，但包含资料从未给出的保证。

<a id="s3"></a>

## 训练数据怎样产生

Self-RAG 先构造并训练 critic，让它判断上述反思标签。部分监督信号由 GPT-4 标注得到，再训练内部 critic 扩展标注。随后将检索段落和反思 token 插入训练样本，训练最终生成模型预测这些扩展词表中的 token。[1，§3.2]

因此，最终模型不仅学会输出自然语言，也学会在适当位置输出检索与质量判断。critic 主要在离线数据构建中使用；推理时并不要求始终额外部署一个同等规模的独立评判模型。

这个流程是监督学习式的生成训练。虽然论文受到奖励模型等工作的启发，但不能把它简单说成“用强化学习让模型反思”。若想训练自己的版本，真正要准备的是任务输出、证据、反思标签及其构造流程，而不只是收集成功和失败奖励。

<a id="s4"></a>

## 推理时怎样选择下一段回答

模型先预测是否检索。若需要检索，就取得多个段落，分别评估相关性并生成候选回答片段，再评估片段的证据支持和用途。推理算法利用这些反思概率对候选进行评分和选择。[1，算法 1、§3.3]

论文还允许调节检索阈值、反思评分权重和段落级搜索方式，使系统在检索频率、支持度和输出完整性之间做取舍。

要注意，模型给出的判断仍是预测，不是事实证明。“fully supported”表示模型认为资料充分支持，不保证每个隐含条件都已经检查；阈值更严格也可能丢掉正确但表达间接的证据。

<a id="s5"></a>

## 一个相关却不支持的例子

问题：“重试失败请求是否会重复执行写入？”候选资料 A 说“客户端支持指数退避”，资料 B 说“使用幂等 token 时，相同 token 的请求不重复执行”。

A 与重试有关，可能通过相关性判断；但它无法支持“不会重复写入”。B 能支持带条件的答案：“在使用幂等 token 且满足服务端约定时，可以避免相应重复执行。”如果模型省略这些条件，支持度判断应该下降。

这组教学例子展示反思标签的作用：让系统在输出之前比较不同证据下的候选表述。不过，若训练数据没有充分覆盖条件省略，模型仍可能高估自己的支持度。工程上可以用这种条件变化构造专门的测试集。

<a id="s6"></a>

## 实验能证明到哪一步

论文用 7B、13B 级别模型，在短答案问答、事实核验及长文本生成等任务上比较，关注答案质量、事实性和引用表现。实验中也包含反思训练与推理配置的分析。[1，§4]

理解这些结果时，至少要区分三个变量：基础模型，训练数据，以及带反思控制的推理算法。如果同时改变三个变量，再把全部收益归给“多问了一次自己”，会误读贡献。

引用准确性也有不同层次：引用是否真的支持相邻陈述，回答里的关键事实是否都有引用，最终答案是否完整。这些指标不能相互替代。支持度很高但只回答了一小部分，仍然不是优秀结果。

该论文支持学习式检索控制和自评的价值，但没有证明模型已经能够可靠判断所有领域的证据，尤其不能把模型的自评分当作业务风险的真实概率。

## 项目实现与数据

[AkariAsai/self-rag](https://github.com/AkariAsai/self-rag) 提供训练数据、7B/13B 检查点、检索及不同任务的推理脚本。公开训练集可从 [selfrag/selfrag_train_data](https://huggingface.co/datasets/selfrag/selfrag_train_data) 进入。[2]

阅读实现时，我建议先查看模型词表里的特殊 token，再选一条带检索文档和反思标签的训练样本，最后跟踪推理脚本如何使用对应概率。这样能看清“模型学到的判断”与“程序据此做的决策”之间的分工。

评测资料覆盖 PopQA、ARC-Challenge、健康事实核验，以及 ASQA、FactScore 等长文本相关设置。各任务的数据格式与评价方法不同，不能直接把它们的分数平均成一个通用正确率。

仓库主要围绕论文任务评估组织，并非完整的企业检索服务。直接接入业务需要处理身份、文档权限、检索接口和模型服务预算。本篇核对了资源，没有训练或运行模型。

<a id="s8"></a>

## 总结与看法

Self-RAG 的贡献在于把几个常被混为一谈的判断拆开，并通过训练让它们参与生成控制。它帮助我们从“有没有查资料”进一步问到“为什么查、查到的是否有用、写出的是否受支持”。

如果只能调用外部通用模型，我会借鉴这几个评价维度，但不会把提示词流程称为 Self-RAG 的完整实现。如果能训练和部署专门模型，则可以研究反思标签是否在自己的领域真正校准。最后要相信独立评测，而不是仅凭模型对自己的评价。

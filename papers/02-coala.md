## 一句话理解

把 Agent 看成一个会办事的人：桌上放当前任务，档案柜存过去经历，知识库保存常识，工具箱保存操作方法；决策过程负责把这些东西用起来。[1]

## 它解决什么问题

不同 Agent 论文使用的术语和模块划分不统一，很难比较。CoALA 给出概念框架，让我们能在同一张图里描述不同系统，而不是提出某一种数据库实现。

## 四种记忆分别是什么

| 记忆 | 通俗说法 | 教学例子 |
| --- | --- | --- |
| 工作记忆 | 现在正在用的信息 | 当前告警、目标和已查到的指标 |
| 情景记忆 | 以前发生过什么 | 昨晚一次连接池耗尽的排查记录 |
| 语义记忆 | 已掌握的知识 | 连接数增加可能带来资源竞争 |
| 程序记忆 | 知道怎样做 | 查询连接状态的工具或已验证脚本 |

这些是功能分类，不代表必须建四套数据库。论文还区分外部行动与内部的检索、推理、学习，并用决策过程连接起来。[1，§4]

## 一次决策如何发生

以排查告警为例：先把告警放到工作记忆，检索相关经历和知识；再推理可能原因、选择工具、执行查询；最后把新经历或提炼出的知识写回长期记忆。这段流程是基于框架的教学演绎。

关键是**存入长期记忆也可以是一种学习**，学习不只等于更新模型参数。

## 论文证据与边界

论文主要通过概念分析和对已有 Agent 的组织来论证框架的解释力，并不是用统一排行榜证明 CoALA 比所有 Agent 更强。框架能帮助划分职责，却不保证具体记忆真实、检索准确或工具安全。

## 对基础设施的启示（本文推论）

记录与事实、技能应有不同的写入规则。一次工具调用失败可以自动记录；一个可执行技能是否发布，则需要独立验证。可以共用底层存储，但保留类型、来源和权限边界，避免把临时推测升级为正式知识。

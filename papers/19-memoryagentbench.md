# MemoryAgentBench：通过增量式多轮交互评估大语言模型智能体的记忆

**英文题名：** Evaluating Memory in LLM Agents via Incremental Multi-Turn Interactions

**版本与时间：** 2025 预印本；2026 ICLR  
**主题：** 增量记忆评测  
**原文入口：** [主文](https://proceedings.iclr.cc/paper_files/paper/2026/hash/fd1eff9dd295df50a41f2521942fa31d-Abstract-Conference.html) · [arXiv](https://arxiv.org/abs/2507.05257)  
**核对日期：** 2026-10-23  
**阅读依据：** [正文或技术版本](https://arxiv.org/html/2507.05257v1)；涉及补充稿的内容单独说明。本文为首版通俗解析，不包含独立实验复现。文中的教学例子与“本文推论”不是论文原始实验。

## 一句话理解

把资料分几批交给助手，每批之后都要自己管理记忆；最后看它有没有记对、学会、串起来，以及放下过时的信息。[1]

## 为什么强调增量输入

一次性给整本资料，模型可以在同一个窗口里通读；持续多轮接收信息，则必须决定什么值得保存、怎样整合与如何更新。后者更接近长期 Agent 的信息流。

## 四项能力

| 能力 | 通俗解释 | 教学问题 |
| --- | --- | --- |
| 准确检索 | 找回之前出现的证据 | 某次事件的负责人是谁 |
| 测试时学习 | 利用交互中新给的知识或示例 | 新规则出现后能否应用 |
| 长程理解 | 整合相隔较远的内容 | 分散线索能否拼出结论 |
| 选择性遗忘 | 正确处理被更新或应忽略的信息 | 旧规则作废后还会不会用它 |

论文把已有长上下文任务改造成多轮输入，也构建新的任务，以覆盖这些能力。[1，§3]

## 教学例子：规则持续更新

第一批资料说服务 A 由甲维护；第二批提供许多其他信息；第三批明确说职责已转交乙。后续既要能找回交接事件，也要避免继续把甲当作当前负责人。

正确“遗忘”不一定是把历史全部物理删除：如果问题问原负责人，旧事实仍可能有价值。具体评价要遵从任务定义。

## 论文结果如何理解

作者比较上下文、RAG 与外部记忆等方案，发现没有一种方法全面掌握四项能力。[1，§4] 因而整体平均分之外，应看各能力和输入长度的表现。测试时学习也不自动意味着更新模型参数。

## 对基础设施的启示（本文推论）

评测需覆盖持续写入和更新，而不只测预建索引上的查询。可以记录每轮写入后状态、冲突处理、召回证据与最终回答，方便定位丢失发生在哪一步。选择性遗忘与法规意义上的数据删除应分别设计。

## 与 MemoryArena 的区别

MemoryAgentBench 更突出增量信息管理的能力分解；MemoryArena 更突出跨会话经验对后续行动的作用。两者搭配能避免只会答题却办不成事的盲区。

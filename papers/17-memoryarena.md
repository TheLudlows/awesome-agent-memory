# MemoryArena：在相互依赖的多会话智能体任务中评测智能体记忆

**英文题名：** Benchmarking Agent Memory in Interdependent Multi-Session Agentic Tasks

**版本与时间：** 2026 ICML  
**主题：** 记忆驱动行动评测  
**原文入口：** [主文](https://proceedings.mlr.press/v306/he26am.html) · [arXiv](https://arxiv.org/abs/2602.16313)  
**核对日期：** 2026-10-23  
**阅读依据：** [正文或技术版本](https://arxiv.org/html/2602.16313v1)；涉及补充稿的内容单独说明。本文为首版通俗解析，不包含独立实验复现。文中的教学例子与“本文推论”不是论文原始实验。

## 一句话理解

不是考“你还记得上次说了什么”，而是考“你能否利用上次学到的东西，把这次的事办成”。[1]

## 它补了哪块空白

对话问答可以说明系统能回忆证据，但真实 Agent 还需要行动。单会话工具任务又不一定需要长期记忆。MemoryArena 把记忆与行动放到跨会话、子任务互相依赖的环境里共同测试。

## 如何构造挑战

Agent 在早期任务中与环境交互、获得反馈，形成记忆；后续任务必须利用这些经验继续推进。论文覆盖网页导航、受偏好约束的规划、渐进信息搜索和连续形式推理等任务。[1，§3]

这里“相互依赖”很关键：如果只是把互不相关的问题串起来，很难说明前面写入的记忆真的影响了后面表现。

## 教学例子：连续两天的运维工作

第一天发现某实例只允许只读诊断，并找到了正确的指标入口。第二天排查相关问题时，系统既要用正确入口，也要记住操作限制。如果只复述“昨天不能写”却仍发出写操作，就不能算成功。

这是面向数据库 Agent 的迁移示例，不是论文原始任务。

## 实验告诉我们什么

论文观察到，在部分既有长上下文记忆评测上表现很好的系统，仍可能在多会话执行环境中表现不佳。[1，§4] 这说明“记得住”和“用得好”需要分开测，不能简单把所有失败归因于记忆；规划、工具调用和环境也会造成失败。

## 对评测体系的启示（本文推论）

同时记录任务成功、阶段进度、错误重复次数与成本。设计一组“有前置经验”和“没有前置经验”的可比任务，固定工具与模型，才能判断收益来自记忆还是额外推理。安全约束应由执行层保证，评测检查是否违反约束。

## 建议阅读位置

先看 §3 的任务和交互循环，再看结果分类，尤其外部记忆并非在所有任务中都带来收益的分析。

# TOIS 记忆机制综述：基于大语言模型的智能体记忆机制综述

**英文题名：** A Survey on the Memory Mechanism of Large Language Model-based Agents

**版本与时间：** 2024 预印本；2025 TOIS 期刊版  
**主题：** 综述  
**原文入口：** [主文](https://dl.acm.org/doi/10.1145/3748302) · [arXiv](https://arxiv.org/abs/2404.13501)  
**核对日期：** 2026-10-23  
**阅读依据：** [正文或技术版本](https://arxiv.org/html/2404.13501v1)；涉及补充稿的内容单独说明。本文为首版通俗解析，不包含独立实验复现。文中的教学例子与“本文推论”不是论文原始实验。

## 一句话理解

它像一本“记忆系统设计地图”：先弄清记忆从哪里来、以什么形式保存、怎么读写，再讨论系统有没有因此变得更好。[1]

## 为什么需要这篇论文

很多文章都说自己给 Agent 加了记忆，做的事情却不一样：有的保存对话，有的记录失败经验，有的修改模型参数。直接比较“谁有记忆”意义不大，必须先统一讨论维度。

## 论文怎样组织问题

论文从三个维度整理实现：**来源**包括当前任务内的信息、跨任务经验和外部知识；**形式**区分可读写的文本记忆与编码进模型参数的记忆；**操作**包括写入、管理和读取。[1，§5]

评测也分两层：直接检查记忆是否正确，或观察加了记忆后，对话、问答和其他任务有没有改善。本文是综述，主要贡献是整理已有研究与问题，并非提出一个可以靠单项跑分证明最优的新系统。[1，§6]

## 用一个例子串起来

假设数据库 Agent 处理一次慢 SQL：

- 本轮查询计划和监控结果属于任务内信息。
- 上次类似问题的排查过程属于跨任务经验。
- 数据库官方手册属于外部知识。
- 保存排查笔记是文本记忆；用训练改变模型参数是另一条路径。

这是教学例子，不是论文实验。

## 它的边界

综述提供分类和研究视角，不能直接替你决定用哪个数据库、如何保证事务或如何隔离租户。早期预印本与后续期刊版本也应区分，引用时要说明实际使用的版本。

## 对基础设施的启示（本文推论）

设计时先写清“存什么、由谁写、何时失效、如何读取、如何验证”，再选存储。否则很容易把向量索引当成完整的记忆系统。值得产出的是一张需求矩阵，而不是照着综述搭一个无所不包的平台。

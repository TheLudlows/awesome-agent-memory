# 19 篇论文怎样放在一起理解

以下是基于各篇解析的教学对照，不是性能排行榜。具体方法与来源见对应文章；右列为本文的工程理解。

## 各自解决什么

| 论文／工作 | 主要对象 | 核心机制或评测焦点 | 工程启示 |
| --- | --- | --- | --- |
| [TOIS 记忆机制综述](../papers/01-memory-survey.md) | 分类地图 | 来源、形式、写入、管理与读取 | 判断讨论的是哪一种记忆 |
| [CoALA](../papers/02-coala.md) | 工作／情景／语义／程序记忆 | 检索、推理、学习与行动的统一框架 | 划分功能与写入权限 |
| [Generative Agents](../papers/03-generative-agents.md) | 经历与反思 | 按相关性、重要性、最近访问程度检索后规划 | 事实与推导分开 |
| [Reflexion](../papers/04-reflexion.md) | 失败经验 | 反馈 → 文字反思 → 下一轮尝试 | 经验必须可执行并有证据 |
| [Voyager](../papers/05-voyager.md) | 可执行代码技能 | 描述检索与技能组合 | 技能需要版本和验证 |
| [MemoryBank](../papers/06-memorybank.md) | 对话、事件总结和用户画像 | 检索、遗忘与强化 | 区分临时事件与稳定偏好 |
| [LongMemEval](../papers/07-longmemeval.md) | 长期对话中的五类能力 | 索引、检索、阅读分阶段评测 | 定位答错发生在哪一层 |
| [MemoryOS](../papers/08-memoryos.md) | 近期对话、主题和长期个人信息 | 分层更新与主题／页检索 | 层级是逻辑组织 |
| [Mem0](../papers/09-mem0.md) | 候选事实与实体关系 | 提取后比较旧记忆并执行增删改 | 语义决策不等于可靠事务 |
| [MemGPT](../papers/10-memgpt.md) | 窗口内工作区与外部历史 | 函数调用调入调出信息 | 管理有限上下文预算 |
| [HippoRAG 2](../papers/11-hipporag2.md) | 段落、实体短语与联系 | 检索起点、LLM 识别与 PPR | 图帮助召回原文证据 |
| [A-Mem](../papers/12-amem.md) | 结构化笔记及其链接 | 生成笔记、建立联系、更新语义描述 | 解释更新后索引也要更新 |
| [LightMem](../papers/13-lightmem.md) | 经过压缩与主题组织的信息 | 轻量在线写入与离线维护 | 计算后台总成本 |
| [Hindsight](../papers/14-hindsight.md) | 事实、经历、综合观察与观点 | retain、recall、reflect 与多路检索 | 区分知道什么与相信什么 |
| [ReasoningBank](../papers/15-reasoningbank.md) | 跨任务推理策略 | 从成功与失败经验提炼并复用 | 策略需要适用范围与反例 |
| [Memory-R1](../papers/16-memory-r1.md) | 记忆操作与利用策略 | 强化学习训练管理者和回答者 | 策略层与存储执行层分开 |
| [MemoryArena](../papers/17-memoryarena.md) | 跨会话行动中的经验价值 | 相互依赖子任务与环境反馈 | 记住还要用得上 |
| [LoCoMo](../papers/18-locomo.md) | 长期对话理解 | QA、事件总结、多模态生成 | 固定数据版本和任务协议 |
| [MemoryAgentBench](../papers/19-memoryagentbench.md) | 增量信息管理四类能力 | 多轮接收后检索、学习、理解与遗忘 | 持续写入也要评测 |

## 三类容易混淆的“学习”

| 方式 | 改变什么 | 本清单中的代表 |
| --- | --- | --- |
| 通过上下文和外部记忆改进行为 | 经验、知识或技能存储，以及后续输入 | Reflexion、Voyager、ReasoningBank |
| 训练记忆管理策略 | 管理和回答策略的模型参数 | Memory-R1 |
| 用增量任务测试学习能力 | 这是评测设置，不限定实现方式 | MemoryAgentBench |

不能因为论文说“self-evolving”或“continual learning”，就推断它在每次交互时训练模型参数。

## 四个评测各测哪一层

| 评测 | 重点 | 可以回答的问题 | 还需额外验证 |
| --- | --- | --- | --- |
| LongMemEval | 长期交互中的提取、更新、时间、跨会话推理与拒答 | 助手能否正确处理不断变化的历史 | 跨任务工具执行 |
| LoCoMo | 长期对话及事件关系的理解 | 人物、事实、时间是否串对 | 真实长期用户数据与执行闭环 |
| MemoryAgentBench | 增量信息流中的四项记忆能力 | 持续接收时有没有记对、整合和更新 | 相互依赖的复杂行动任务 |
| MemoryArena | 跨会话记忆与行动的耦合 | 前面形成的经验是否帮助后面的事 | 特定业务环境与系统可靠性 |

四者互补。加入记忆后任务成功率提高，并不自动说明每个记忆组件都有贡献；需要公平预算和消融。

## 常用术语

| 术语 | 通俗解释 |
| --- | --- |
| 工作记忆／context | 模型这次推理实际能看到的材料 |
| 情景记忆／episodic memory | 某次发生过的事情或执行经历 |
| 语义记忆／semantic memory | 从经验或外部资料得到的知识；这里不是专指向量 |
| 程序记忆／procedural memory | 操作方法、代码或技能 |
| 反思／reflection | 从经历中总结更高层认识；结论可能出错 |
| 记忆巩固／consolidation | 把零散信息整理成更稳定、可用的表示 |
| 非参数记忆 | 外部存储的知识，更新不要求改变基础模型参数 |
| PPR | 从相关节点出发传播分数，并偏向返回这些节点附近的图排序方法 |
| RRF | 根据多个候选排名融合结果，减少直接比较不同原始分数的问题 |
| 消融实验 | 移除或替换组件，观察效果是否变化 |
| 选择性遗忘 | 不再沿用无效或过时的信息；不自动等同于物理删除 |

## 对记忆基础设施的一种分工（本文推论）

底层保存原始证据、元数据、版本和检索索引；上层负责提取事实、建立联系、生成反思、维护经验与管理上下文。可靠性需要明确以下接口语义：

- 新记忆何时可读，后台索引未追上时能否找到它。
- 事实更新怎样区分历史真相、当前状态与未来计划。
- 生成的摘要、观点和技能怎样追溯到证据。
- 权限、租户作用域和删除规则怎样应用到原文及派生内容。
- 如何观察写入、召回、排序、阅读与行动各阶段。

这是一种系统设计分析，不是把上述所有要求归为某篇论文的已实现功能。
